02 / Architecture

A coherent multi-client system.

The boundaries are legible: clients share player and API semantics, the backend owns authorization and persistence, and external integrations sit behind server-side adapters.

Key design trade-off: core ships raw TypeScript. Web compiles it directly; mobile syncs a generated copy because Metro cannot follow the repository boundary. The sync check is automated in CI, which contains most—but not all—of the drift risk.

03 / Findings

Seven open. Three resolved.

Original finding IDs and severity are preserved in the narrative. Resolved cards show the implemented change and the verification evidence collected after remediation.

F-01 · original blockerResolved

The Filen downloader dependency blocker is closed

The helper now pins @filen/sdk 0.4.2, overrides its legacy Axios range with axios 1.20.0, and replaces the vulnerable js-crypto-key-utils → elliptic path with a small Node crypto compatibility package limited to the SDK’s DER-to-PEM contract. The backend image copies that local package before its reproducible npm ci --omit=dev install.

npm audit --omit=dev: 0 vulnerabilitieselliptic absent from production tree8 helper contract tests pass@filen/sdk 0.4.2

Verified remediation
Fresh production install, SDK surface compatibility, authenticated file and folder-link flows, complete-download reuse, DER/PEM/JWK conversion, truncated-download rejection, and partial-file cleanup all pass. A full container build could not run in the review environment because its Docker socket is unavailable.

F-02High

Build and runtime bases have crossed their support windows

CI and the frontend build image use Node 20; the backend pins Go 1.24.1 / golang:1.24-alpine; the backend runtime is Alpine 3.20. At the review date, Node 20 and Alpine 3.20 are end-of-life, while Go 1.24 is outside Go’s two-release support window. Reproducible digests are good, but frozen obsolete digests also freeze missed security maintenance.

.github/workflows/ci.yml:20,44,61,84frontend/Dockerfile:1backend/Dockerfile:1,8backend/go.mod:3

Action
Move build jobs to Node 24 LTS, test the backend on Go 1.26.x or 1.27, and refresh Alpine to a supported branch such as 3.24. Keep digest pinning and schedule automated refresh PRs. Sources: Node release status, Go support policy, Alpine branches.

F-03High

The release workflow can publish while verification is failing

Tag pushes start both CI and release workflows, but the desktop build depends only on its own prepare job. It builds and publishes assets without waiting for backend tests, client lint/tests, or an audit gate. A red CI run can therefore coexist with successfully published release artifacts.

.github/workflows/release.yml:33–41,84–89,136.github/workflows/ci.yml:3–8

Action
Make release consume a reusable verified-build workflow, or gate publishing on a successful CI workflow for the exact tag SHA. Add a pre-publish dependency scan. Keep current wording explicit: CI desktop artifacts are unsigned, macOS auto-update is unsupported, and they are not distribution-ready notarized builds.

F-04High

The entire web/Electron surface has no automated tests

The frontend still has no test files and no test script. The Electron main process has been reduced from 1,734 to 828 lines and its proxy, FH6, Discord, and configuration services now have explicit module boundaries, which improves testability—but compilation alone still does not protect navigation, auth flows, player integration, IPC permissions, updates, admin mutations, or share behavior.

frontend/package.json: no test scriptfrontend/electron/main.ts: 828 linesfrontend: 0 test files

Action
Add Vitest + Testing Library around auth/reset, player/queue, routing, share dialogs, and admin flows. Extract Electron IPC/updater/config units behind interfaces and test allowlists, path handling, window lifecycle, and failure behavior.

F-05Medium

Mobile CI omits both lint and a formal typecheck step

The mobile CI job installs, verifies the synced core copy, and runs tests—but still does not run npm run lint or a formal typecheck script. The local warning backlog is now closed and the lint script enforces --max-warnings=0; the remaining gap is making CI execute those checks.

.github/workflows/ci.yml:75–96mobile lint: 0 warningsnpx tsc --noEmit: pass

Action
Add a typecheck script, then run typecheck and the now-strict lint command in mobile CI so the clean local state becomes an enforced merge condition.

F-06Medium

Web and mobile lockfiles contain additional production advisories

The web audit reports three vulnerable packages: a direct React Router advisory set and transitive js-yaml. Mobile reports 21 entries across Expo/Metro and nested tooling; several are build-time paths despite npm classifying the Expo tree as production, so the raw count needs reachability triage rather than alarmist treatment.

frontend: 1 high · 2 moderatemobile: 21 audit entriesreact-router-dom 6.30.4js-yaml 4.3.0

Action
Patch React Router first and test every redirect/navigation input; see the open-redirect/XSS advisory. Refresh js-yaml to 4.3.1+ where compatible. For Expo, use an Expo-compatible dependency upgrade plan—do not accept npm’s suggested framework downgrades without review.

F-07 · original mediumResolved

Hook correctness now has a zero-warning budget

The previous 3 core, 38 frontend, and 26 mobile warnings were triaged. Dependency, render-time ref, purity, and immutability cases were refactored where appropriate; intentional external-state synchronization and framework-owned mutable cells use narrow, documented suppressions.

core lint: 0 warningsfrontend lint: 0 warningsmobile lint: 0 warnings--max-warnings=0 enforced

Verified remediation
All three package lint scripts now fail on any warning. Core typecheck and 86 tests, frontend typecheck/build, and mobile TypeScript validation pass after the hook changes.

F-08Medium

Backend tests are broad in count but shallow at persistence boundaries

Thirty-nine Go test files cover many failure cases, yet statement coverage is 24.4% overall. The most stateful domains are especially thin: library 1.0%, Filen 3.9%, ingest 6.5%, playlists 7.8%, and HTTP handlers 19.4%. Database migrations, router composition, users, invites, and music roots have no direct statement coverage.

go test ./... -coverprofilebackend: 33,353 Go lines17 migrations

Action
Add Postgres-backed integration tests for migration up/down, ownership and collaborator transactions, ingest deduplication, and admin deletion. Use coverage as a map, not a quota: prioritize invariants and rollback behavior.

F-09 · original mediumResolved

The five cited responsibility bottlenecks have been split

Each hotspot now delegates a cohesive concern: Electron proxy/FH6/Discord/configuration services, shared API transport/media/integration/auth contracts, mobile playlist-header presentation, public story rendering, and API-tracker metadata normalization. Public interfaces and behavior remain intact.

Electron main: 1,734 → 828shared API: 1,669 → 990playlist detail: 1,306 → 786share handler: 1,210 → 1,000scanner: 1,152 → 928

Verified remediation
Go tests, core lint/typecheck/tests, frontend lint/typecheck/build, Electron compilation, and mobile lint/typecheck all pass across the extracted boundaries.

F-10Low

The internal TIDAL sidecar relies entirely on network trust

The Python extension’s account and device-auth routes do not authenticate callers. Compose keeps the service off host ports and the Go backend correctly protects its public admin facade, so exposure is limited. Still, any compromised sibling container or future network topology change gains credential-management access.

hifi-api/lumen_hifi.py:220–479docker-compose.yml: hifi-api expose only

Action
Add a shared service token on the Go→sidecar calls or bind a Unix socket/private loopback in a shared namespace. At minimum, document the private-network assumption and add a deployment check that the sidecar never publishes a host port.

04 / What is working

Security intent is visible in the code.

The review found multiple places where the implementation anticipates real failure and abuse modes rather than stopping at happy-path correctness.

01

Authentication fundamentals

Argon2id with sensible parameters, constant-time comparison, dummy verification for unknown users, random session tokens stored as hashes, expiration cleanup, and HttpOnly/Secure/SameSite cookies.

02

HTTP boundary hardening

Trusted-proxy-aware client IP handling precedes rate limiting; unauthenticated, user, and admin routes are separated; ordinary, upload, image, and preview work receive distinct deadlines.

03

File and network safety

Upload size limits, path containment helpers, non-root runtime users, bounded response reads, HTTP client timeouts, HMAC-signed public media, and redirect-aware SSRF checks for remote artwork.

04

Operational lifecycle

Graceful HTTP drain, cancellation-aware background workers, panic isolation, worker accounting, health checks, scanner timeouts, and explicit session cleanup show mature server ownership.

05

Reproducibility and containment

Lockfiles, action SHA pins, image digests, dropped Linux capabilities, no-new-privileges, resource ceilings, loopback host bindings, and a non-root nginx deployment are all strong defaults.

06

Shared semantics, not duplicated business logic

The API, auth, favorites, player state, and activity protocol live in one core package. Mobile’s copy step is explicit and checked, while platform-specific audio/storage adapters remain outside core.

07 / Scope

What this review does—and does not—claim.

Precision matters. This is an evidence-backed repository review, not a substitute for runtime testing in the actual deployment environment.

Included

  • Repository architecture and component boundaries
  • Security-sensitive auth, network, file, and container paths
  • CI and release workflow behavior
  • Format, vet, typecheck, lint, build, compile, and unit tests
  • Live npm production-dependency audit on 29 August 2026
  • Official runtime lifecycle status

Not included

  • Live penetration test or production configuration review
  • Postgres-backed end-to-end test environment
  • iOS/Android device builds and native-module runtime testing
  • Desktop installer packaging, signing, notarization, or Gatekeeper verification
  • Load, chaos, accessibility, or media-compatibility testing
  • Container CVE scan, SBOM attestation, or secret-history scan
